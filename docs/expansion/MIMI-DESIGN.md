# Mimi 第一批扩展设计：12 个动作 + 8 个功能

状态：设计提案，尚未实现或制作新图片。由主代理整理；不以其他代理文档为交付依据。
目标：让 Mimi 更有生命感，也更实用；不靠大量菜单、频繁气泡和机械奖励堆功能。

八项功能的完整交互、状态、数据与验收规格见 [八项功能详细设计](FEATURE-SPEC.md)。本文件保留首批范围和动作总览。

## 1. 现状与边界

当前 manifest 声明 23 套正式动作，22 个拖拽力度点另计。已有摸头、戳脸、击掌、投喂、走路、坐下睡觉、欢迎回来及工作反应，不算新增。
现有专注、一次性提醒、勿扰、系统媒体控制也不重新包装计数。本设计只列有新增行为或交互的条目。
源码核对点：`action_library.py` 只加载可用素材白名单；`engine.py:312` 的 perform 仅从 IDLE 开始；force_perform 也保护拖拽、坠落、落地、睡眠和关闭状态。
不把未经制作的动作写进 usable_actions；缺素材时保持现有待机，不拿一段旧动画冒充新动作。

## 2. 十二个新动作

优先级：P1 为用户主动触发，P2 为功能事件，P3 为低频氛围；物理状态保护高于所有表演。
“退出”统一要求恢复正确脚底根节点、清除道具层和定时器；被打断不补播，不排队骚扰。

| ID | 动作与视觉描述 | 触发、节奏 | 素材路线 | 完成与打断验收 |
|---|---|---|---|---|
| A01 stretch | 伸懒腰：双手举起、舒展身体再放松 | P3，普通空闲超过 20 分钟后才有资格；每日最多 3 次 | 新绘制 12–18 帧；保持服装和脸部身份 | 约 3 秒回站姿；用户点击或拾取立即让位；勿扰不自主触发 |
| A02 drink_water | 抱杯喝水：拿起小杯、喝一口、放回 | P2，用户点击健康卡“我也喝水”；不按系统时间强制演 | 新绘制 16–24 帧 + 杯子道具；不是现有面包投喂 | 3–4 秒结束、杯子消失；拖拽时取消，实际喝水记录独立于动画 |
| A03 peek_note | 展开便签：举起折叠便签、侧身让出内容卡 | P1，用户打开 F01 随手记 | 新绘制 10–16 帧；内容为独立 Qt 文本层 | 打开约 1.5 秒，收起约 1 秒；收起和卡片关闭同步，不残留遮罩 |
| A04 think_pencil | 铅笔思考：拿铅笔、轻点下巴，等待用户决定 | P2，仅 F02 用户主动开始拆任务时；不是 DSH 普通思考替换 | 新绘制开场/循环/结束，总计约 20–28 帧 | 循环最长 8 秒，卡片仍可用但动画回待机；用户输入不被抢焦点 |
| A05 tidy_desk | 整理小桌面：摆正自己的小书和笔，收好道具 | P1，用户关闭 F07 布景时播放；不移动真实文件 | 新绘制 18–24 帧 + 宠物道具层 | 4 秒以内；拾取取消后直接清道具，不留下碰撞实体 |
| A06 scarf_adjust | 整理围巾/蝴蝶结：扶正装饰、满意地看一眼 | P1，F05 配饰保存成功后 | 新绘制 10–16 帧；配饰锚点需要校准 | 约 2 秒，装饰不漂移；换装失败不播放成功反馈 |
| A07 ribbon_spin | 展示配饰：小幅转身展示，再回到原位 | P1，用户点“预览穿搭”；非普通庆祝 | 新绘制 18–24 帧，逐套配饰检查遮挡 | 约 3 秒；角色不越屏、不改变世界坐标；低动态模式改静态预览 |
| A08 search_pockets | 摸口袋找东西：寻找后拿出用户选定的小物件 | P1，F06 玩具盒选择物品 | 新绘制 16–22 帧，物品为白名单图片 | 3 秒拿出目标物，无目标则不开始；取消后清物品、无背包扣减 |
| A09 ball_roll | 推小球：轻推球、目光追踪、球慢慢停下 | P1，F06“玩一会儿”；每轮最多 20 秒 | 新绘制推球姿势 + 球精灵 + 独立轻量轨迹 | 不跨显示器缝隙、不挡输入；拾取/按 Esc 立即收球；不使用虚假全局鼠标操作 |
| A10 catch_star | 接星星：伸手接住一颗落下的纸星星，放入盒中 | P2，F02 一个子步骤由用户确认完成 | 新绘制 12–18 帧 + 星星特效；不同于现有击掌/庆祝 | 2.5 秒内完成；一组完成事件只演一次，突发事件合并 |
| A11 headphone_listen | 戴耳机听歌：戴上耳机、轻轻点头，结束后取下 | P1，F04 用户开启“陪我听”；检测到音乐不自动开启 | 新绘制佩戴/摘下各 8–12 帧；小幅点头可参数合成 | 没有节拍分析时仅标“舒缓摆动”；静音/停止跟听 5 秒内摘下；低动态时静止 |
| A12 lantern_goodnight | 收起小灯：放下小灯、挥手道别，淡出布景 | P1，F03 用户主动结束今天；不重复现有入睡动作 | 新绘制 14–20 帧 + 灯光渐变；非必须关机动作 | 3 秒后退出仪式；不关电脑、不结束 DSH 任务；勿扰保持无声 |

帧数是制作估算，不是既有资产数量。先做关键帧与灰模，视觉验收通过才补帧；无原始分层源图时不承诺自动生成一致的新姿势。

## 3. 八个新功能

| ID | 功能 | 用户交互与价值 | 依赖与边界 | 可测验收 |
|---|---|---|---|---|
| F01 | 随手记便签 | 桌宠菜单“记一下”→ 小卡片输入 → 保存；支持编辑、归档、搜索；配 A03 | 新本地 notes 存储和卡片，文本默认 2000 字；不自动读取剪贴板 | 重启可恢复；中文输入不误发送；删除有一次撤销；不触发模型调用 |
| F02 | 三步任务陪跑 | 用户输入一件事，自行拆为最多 3 步→只显示当前一步→用户手动打勾；A04/A10 做反馈 | 新 task_run 数据；与专注计时和 DSH job 分开；首版不让模型自动拆解、不自动判完成 | 步骤次序与勾选可恢复；撤销勾选不扣好感；取消不再弹提醒；完成事件去重 |
| F03 | 下班收尾卡 | 用户主动点“今天到这里”→勾选收尾事项、留明日第一步、选择保留或隐藏布景；A12 收尾 | 复用 F01/F02 的明确记录，单独仪式状态；不推断真实工作表现 | 不关闭程序、不取消 DSH 工作、不改提醒；次日一键找回明日第一步 |
| F04 | 陪我听音乐 | 在现有媒体栏新增跟听开关与强度；开启后 A11 轻摆，暂停时安静等待 | 复用 SMTC 播放状态；不录音、不假称识别 BPM；无 winsdk 时禁用并说明 | 开关默认关；暂停/停止后 5 秒内停止摆动；频繁曲目变化不重播佩戴动画 |
| F05 | 小衣帽架 | 三个配饰槽：头饰、颈饰、小挂件；支持试穿、撤销、保存，A06/A07 展示 | 白名单配饰、manifest 锚点和遮挡规则；首版只保证待机姿势适配，其他动作明确隐藏配饰 | 试穿不覆盖已存方案；切动作不穿模；重启恢复；缺图自动回无配饰 |
| F06 | 桌边玩具盒 | 用户选择纸星、小球等；一轮有开始/结束，A08/A09 参与；不是无限点击刷好感 | Qt 道具层和游戏会话；不模拟系统输入；窗口避让且可一键收起 | Esc、拾取、关闭玩具盒均释放对象和计时器；退出后待机资源占用回到基线 |
| F07 | 可收起的小布景 | 选择书角/小灯/小垫子等“宠物自己的空间”，支持拖动布局、保存和一键清空 | 独立装饰层；不读取用户窗口内容；自由布局与宠物物理碰撞先分离 | 不遮住输入卡/问题卡；多屏断开回可见区域；关闭后不留透明输入屏障 |
| F08 | 温柔的健康小卡 | 用户选择喝水、看远、肩颈舒展，配置工作时段、间隔、每日上限；卡片可完成/稍后/今天关闭 | 在一次性提醒之上新增重复计划和执行记录；非医疗建议、不识别摄像头、不记录健康隐私细节 | 休眠不补发一串卡；勿扰只收进待处理；每天上限生效；今天关闭后当日不再出现 |

## 4. 第一阶段只做 3 动作 + 2 功能

选择：A02 喝水、A03 展便签、A10 接星星；F01 随手记、F02 三步任务。
理由：便签和三步任务不用接新云服务即可实用；展便签与接星星和功能形成明确反馈；喝水是独立可点播的动作，待 F08 再接重复计划。
允许 F01/F02 先以普通卡片交付；美术未完成时功能可用、动画不启用，不拿旧动画假装新动作。

实施顺序：
1. 建本地数据层：独立 `notes_store.py` / `task_run_store.py`，路径放用户数据目录；带 schema_version、原子保存、坏档备份和输入上限。
2. 增加卡片：F01 文本编辑/搜索/归档；F02 3 步编辑/当前步骤/撤销/完成。不扩大现有 companion.py 为杂物箱。
3. 完成 A02/A03/A10 的关键帧、根节点与服装一致性验收，再导出逐帧素材。
4. 扩展动作请求器、事件去重与道具层，然后挂接 F01/F02；新动作只在素材验收后启用。
5. 做关闭/重启/拖拽中触发/勿扰/高 DPI/多显示器回归测试。

## 5. 代码接入位置与最小结构

- `action_library.py`：保留严格白名单；为新动作做重复 ID、路径限制、最大帧数与时长校验。
- 新增 `action_director.py`：仲裁请求，不让每个功能直接调用 force_perform；记录 request_id/source/priority/expires_at/cooldown/interrupt_policy。
- `engine.py`：保持物理优先；已有 perform 从 IDLE 进入，Director 只在允许状态提交。先不增加十二种 PetState，动作仍属 PERFORMING。
- `renderer.py`：为便签、星星、杯子建立可释放的道具层；层级顺序为布景→角色后道具→角色→前道具→气泡/问题卡。
- `qt_app.py`：只负责装配服务、注册事件与统一关闭；不把新业务流程直接塞进 tick 回调。
- `lib/client.js`：为 F01/F02 添加明确入口或分区，不挤满原专注提醒表单；Python 卡片与 Web 共享服务数据，避免两套各存一份。
- `companion_protocol.py` / `companion_ipc.py` / `pet-runtime.js`：如果承载新增操作，须三端同步定义 op、版本、长度上限和错误；现有宿主 OPS 白名单也要同步，绝不只改 Python。

建议数据：Note{id,text,created_at,updated_at,archived}; TaskRun{id,title,steps[{id,text,done}],status,updated_at}。
事件：note.opened、task.step.completed、task.run.completed；使用 event_id 去重，回放历史不再次触发动画。
本轮不把示例字段直接加入当前生产 manifest 或 RPC，避免旧端误读。

## 6. 调度与低打扰约束

1. 拖拽、坠落、落地、关闭优先保护；新功能事件不得取消用户触摸或系统物理动作。
2. 问题/批准卡保持可点击，不依赖动画完成才显示；表演无权盖住问题卡。
3. 用户动作 > 业务事件 > 氛围；氛围不排队；业务事件只保留最新一条且 5 秒过期。
4. 同动作默认冷却 60 秒；用户明确重播可绕过氛围冷却，但仍保护物理状态。
5. 勿扰禁止自主氛围和普通业务动画；用户主动预览仍可播放。低动态模式用静态卡片，不做摆动/闪光。
6. UI 关闭、功能禁用、进程退出均取消道具生命周期；不补播积压动作、不用好感惩罚用户忽略卡片。
7. 图片按需加载、缓存有预算，当前 ImageCache 无淘汰机制；扩展前增加按解码尺寸计费的 LRU，不凭帧压缩文件大小估计内存。

## 7. 素材与验收

- 沿用当前动作标准画布 512×768、脚底 pivot (256,744)；Rig 当前是 1024×1536，注册按现有固定尺度处理。
- 不按每帧透明包围盒自动 fit；道具不改变角色缩放；关键帧服装、发型、脸型必须一致。
- 单独记录前/后道具遮挡、手握接触点、表情是否锁定、开场/循环/结束，给每段定义最大循环时长。
- 验收包含：首尾衔接、拖拽取消、素材缺失、重复事件、保存失败、重启恢复、低动态、125%/150%/200% DPI、双屏拔除。
- 自动测试先覆盖状态与数据，不把“能加载图片”当作视觉验收；逐帧接触点与身份一致性需人工看图。

交付边界：本文件包含恰好 12 个动作设计、8 个功能设计和可分批实施方案；未新增运行功能、未制作新动作素材、未进行 GUI 验收。
