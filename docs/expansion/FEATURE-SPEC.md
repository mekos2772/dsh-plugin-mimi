# Mimi 八项功能详细规格

版本：设计稿 1.0；状态：尚未实现。本稿深化既定 F01–F08，不新增第九项主功能。

最新范围调整：F05 已从自由配饰衣帽架改为预设造型册；F04 首版改静态跟听，不动态叠加耳机。范围、优先级与动作兼容策略以 [最新开发清单](ROADMAP.md) 为准；本稿 F05 及其他动态配饰相关描述作为历史备选，不直接实施。
目标用户：在 DSH 工作时希望桌宠既有陪伴感，又能帮助记事、推进小事和温柔收尾的人。
决策原则：主动操作优先、本地计算优先、状态可信优先于动画、可随时退出、不用关系值绑架用户。

## 0. 公共产品与技术约定

### 0.1 入口与导航
- DSH 顶部继续保留一个 Mimi 入口，不增加八个顶栏按钮。面板分为「今天」「小空间」「设置」三级入口。
- 「今天」：当前三步任务、随手记快捷输入、健康待处理、收尾入口；原专注/提醒入口保持可达，不改原操作语义。
- 「小空间」：衣帽架、玩具盒、布景；音乐入口仍以现有媒体栏为主，此处显示跟听开关。
- 「设置」：低动态、通知频次、导出/清除数据、各功能独立开关、存储状态。
- 桌宠菜单首层只放「记一下」「当前一步」「小空间」「今天到这里」；其他入口放二级菜单，避免超长菜单。
- Python 快捷卡片用于当前操作，DSH 面板用于列表和管理。同一时刻只出现一张主动编辑卡，切换前保存草稿，不抢正在回答问题的焦点。

### 0.2 数据所有权与保存
- Python 内的独立服务是这八项数据的唯一写入者；Node 只转发请求和缓存快照，Web/Qt 不直接同时编辑 JSON。
- 建议新增扩展数据目录：Windows `%APPDATA%/MimiDesktopPet/expansion/`，其他平台为用户数据目录；路径可用单个配置覆盖。
- 分文件：notes、task_runs、wrapups、appearance、scene、health；所有文件带 schema_version，采用临时文件、flush/fsync、原子 replace；损坏原件保留备份。
- 首版与现有 JSON 存储保持一致，不引入数据库；跨文件操作采用可恢复 outbox 命令，不宣称多个 JSON replace 构成原子事务。
- 编辑项带 revision。更新提交 expected_revision；过期则返回 conflict 和最新内容，不静默覆盖；编辑草稿与已提交实体分离。
- 保存成功才显示“已保存”。失败显示“尚未保存”，保留当前草稿与重试按钮；明确导出草稿后才允许用户主动放弃。
- 相互引用采用 ID，不复制业务状态。例如收尾引用任务 ID，但保存必要的标题快照以防源任务后来归档。

### 0.3 协议与性能预算
- 当前宿主仅支持 state/action/start；HTTP 文本上限 8192，PetRuntime 还有操作指纹长度限制。新操作不可只加入 Python 白名单。
- 建议扩展版新增 query 端点与 query 帧；动作仍走 action。index.js、pet-runtime.js、companion_ipc.py、路由器、client.js 必须同时升级。
- ready 握手增加 capabilities、protocol_version；旧端看不到能力时隐藏新入口并说明需升级，不盲发新 op。保留原有 state/action 兼容路径。
- 每次写操作带 request_id；重试使用同 ID，服务缓存结果。expected_revision 防止两个不同写请求互相覆盖；去重缓存重启丢失时，操作本身还须由状态或持久事件键保障可重试。
- state 只带汇总计数、当前任务和服务 revision，不每秒广播所有便签正文。列表 query 分页，每页最多20项；每个响应编码后不超过64 KiB。
- 中文 2000 字可能在 JSON 转义后超过现有信封限制。不得简单放大限制：按最终编码信封做4096字符/16 KiB双预算校验；超预算采用分块草稿上传、校验后一次提交。
- 扩展草稿上传单块 UTF-8 不超过2 KiB，带序号与整体摘要，最多32 KiB/草稿，2分钟未活动过期；缺块或摘要不符不提交，最多8个未提交草稿。
- UI目标：本地查询在1000条便签规模下95%小于200ms；事件循环不执行网络或大批图片解码。最终需在基准机实测，当前不是性能保证。
- 图片缓存新增解码字节预算和 LRU，默认64 MiB、低内存档32 MiB；当前画面资产可暂时固定，但需明确统计是否超预算。

### 0.4 动画、权限、通知
- 动作是业务结果的订阅者，不决定业务是否成功。缺图、动画被抢占、低动态均不丢记录。
- ActionDirector 保护拖拽/坠落/落地/关闭状态；物理 > 用户直接互动 > 用户明确预览 > 业务反馈 > 自主氛围。
- 问题/批准交互始终可达。业务动画5秒过期、氛围不排队；同事件只播一次，历史回放不触发。
- 勿扰禁止自动气泡和普通业务动画，待处理事项仍可在面板查看；用户明确点击的预览可播。低动态改静态卡，系统减少动态偏好优先。
- 八项功能默认不新增外网请求、摄像头、录音、截屏、全局键鼠监听或自动读取剪贴板；SMTC 只使用既有媒体接口。
- 所有本地数据可导出、单项清除；日志仅记录ID、错误类型和耗时，不记录便签正文或健康内容。

## F01 随手记便签：把想法留下，不打断手头事

### 用户场景与范围
用户正在写代码，临时想到一个要点，点“记一下”输入，保存后马上继续；之后可搜索、整理或转成三步任务。
首版是本地文本便签，不是云笔记、文件管理器或知识库；不自动采集用户正在看的内容。

### 页面结构
- 快速卡：标题「记一下」、多行正文、字符计数、保存状态、保存并收起/取消；占位文案“先记下来，稍后再整理”。
- 管理页：搜索框、全部/置顶/归档/最近删除；列表显示首行、更新时间和标签，不直接展开全文。
- 详情页：正文、最多5个标签、置顶、归档、转为任务、删除；正文保留换行，作为纯文本显示，不执行 HTML。
- 中文输入法组合输入中的 Enter 只用于选字；换行用 Enter，Ctrl+Enter 提交；按钮始终可点击，macOS 快捷键适配为 Cmd+Enter。

### 完整流程
1. 首次打开新建空草稿，主动操作才把焦点给编辑框；播放 A03 与否不影响可输入。
2. 允许正文1–2000个 Unicode 字符，标题由第一行派生，列表截短但正文不截断；空白内容不提交。
3. 停输1秒写入 draft 暂存，不等于“正式保存”；显示“草稿已暂存”。
4. 点击保存：提交 request_id、expected_revision 或新建标志；成功后显示“已保存”，默认收起。
5. 归档可恢复；删除进入最近删除，保留7个本地日历日，永久删除须确认；刚删除提供10秒撤销。
6. 搜索只匹配标题、正文、标签，大小写归一；不搜索 DSH 会话或其他文件。
7. “转为任务”打开 F02 预填草稿，不自动提交；任务保存成功后再为便签添加 task_id 引用，原便签保留。

### 状态与数据
编辑状态：idle → editing → saving → saved；失败进入 unsaved，冲突进入 conflict。
实体状态：active ↔ archived；active/archived → trashed → restored 或 purged。
Note{id,body,tags,pinned,status,created_at,updated_at,deleted_at,revision,linked_task_ids}；Draft{id,note_id,base_revision,body,updated_at}。
默认上限1000条未永久删除便签；达到上限提示导出/清理，不静默删除。标签单个最多16字符。

### 异常与联动
- 多端冲突：展示“原版本/对方版本/我的草稿”，可复制或另存；首版不做自动三路文本合并。
- 换页/关卡片/退出时先尝试暂存；磁盘失败明确告知，保留内存稿，用户可复制文本。
- A03 只在主动打开时触发，搜索和每次自动暂存不重播。反复开合30秒内只播一次。
- 导出为 UTF-8 Markdown/JSON；用户选路径才写文件。未来导入须限制大小与schema，不执行文档内内容。

### 后续延伸与验收
延伸：模板便签（问题/想法/待查）、手动关联工作会话、显式粘贴剪贴板；不做后台收集。
验收：2000中文与emoji往返一致；断电重启后已提交便签存在；超限提示；冲突保留两稿；归档/回收站可恢复；保存失败不出现“已保存”；卡片关闭不残留透明拦截窗。

## F02 三步任务陪跑：只把眼前一步变小

### 用户场景与范围
用户面对一件难启动的事，把它写成最多三步，Mimi 只陪当前一步，不把任务列表变成绩效系统。
与 DSH job/模型任务完全分开，首版不自动拆解、不监听文件推断完成、不自动完成复选框。

### 页面结构
- 新建：任务标题（1–80字）、1–3行步骤（每步1–160字），默认给空白输入而不是虚构步骤。
- 当前卡：任务标题、进度1/3、当前一步、“完成这一步”“暂停”“更多”；其他步骤折叠可展开。
- 列表：当前/稍后/已完成/已取消；最多1个 active，20个尚未结束的任务，其余归档。
- 完成页：列出已完成步骤与用户可选一句总结，不展示耗时排名，不催分享。

### 完整流程
1. 用户输入标题和步骤，点“开始陪我做”；已有活动任务则选“暂停原任务并开始”“放到稍后”或返回。
2. 第一个未完成步骤为 current；用户可显式跳过到后一步，但需显示前一步仍未完成，不偷偷勾选。
3. 点击完成先提交状态；成功后更新进度，再请求 A10。连续连点只产生一次变更。
4. 若还有步骤，显示下一步；全部完成进入 completed，不自动新建任务。
5. “撤销上一步”恢复最近一步的完成状态；不扣分、不播负面动作、不再次奖励事件。
6. active/paused 可编辑未完成步骤；已完成步骤修改文字需要明确选择“仅改描述”或“重新打开”。
7. 暂停保留当前位置；取消有确认且可恢复为 paused；归档不等于删除。
8. 可选“配一个专注计时”：显式调用现有计时服务。任务暂停/完成仅给计时控制建议，不自动取消仍在运行的专注。

### 状态与数据
TaskRun：draft → queued → active ↔ paused → completed；queued/active/paused → cancelled；取消可恢复 paused。
TaskStep：pending ↔ done；current_step_id 必须指向 pending 或为空，不将“current”作为第二个可能冲突的状态源。
TaskRun{id,title,steps[{id,text,status,completed_at}],current_step_id,status,source_note_id,focus_session_id,revision,created_at,updated_at}。
TaskEvent{id,task_id,step_id,type,operation_id,created_at}；动画消费该事件，事件持久化用于重启去重。

### 异常与联动
- A04 只在主动开始拆步时播，最长8秒；等待用户输入不循环催促。
- 离线/重启恢复当前任务与步骤；不在登录后补播所有完成动画。
- F01 转入保留 source_note_id；F03 收尾只提议移至明日，不自动改任务状态。
- 两端同时完成一步：第二个收到最新状态，展示已完成，不再生成新完成事件。
- 业务写成功但UI超时：相同 request_id 重试或query取新revision，不能因动画未播回滚业务。

### 后续延伸与验收
延伸：用户自建三步模板、手动链接 DSH 会话、显式请求模型拆步（独立开启，展示发送内容和成本）。
验收：20次连点完成只变更一次；撤销后current正确；最多一个active；重启无进度丢失；取消无负反馈；任务完成不结束DSH job或专注计时。

## F03 下班收尾卡：给今天一个出口，给明天一个入口

### 用户场景与范围
用户主动结束工作，不想再开新一轮任务。Mimi 帮他留明日第一步，并把自己的布景收好。
它是可跳过的仪式，不是关机工具、工时统计或自动总结聊天内容的功能。

### 页面与流程
1. 入口“今天到这里”，打开收尾草稿，展示日期与“按你想要的方式结束”。
2. 第一步“留下什么”：用户可点选F02任务、手选最多3条便签，或什么都不选；只展示明确记录，不推断完成度。
3. 第二步“明天第一步”：1–160字，自填或从一个待做步骤复制；默认不创建任务或提醒。
4. 第三步“小空间”：保持原样/只关灯/隐藏布景；明确只是宠物布景，不改真实桌面和系统亮度。
5. 确认页列出实际将保存的内容与将改变的小空间选项，点击“收好今天”；任一步可“跳过仪式”。
6. 保存成功后请求A12；动画取消不取消记录。已有任务/计时继续原样；如用户希望暂停，提供独立显式按钮。
7. 下次用户打开“今天”时显示收尾摘要卡与“明天第一步”；日期过去即为“下次第一步”，不制造逾期压力。
8. “接着做”打开F02预填草稿；只有用户保存才建立任务，已有关联则直接打开，不重复创建。

### 状态、数据、联动
Wrapup：draft → saved；saved可修订，修订不重复播结束仪式；动画是临时 presentation 状态，不写入业务状态。
Wrapup{id,local_date,timezone,note_ids,task_ids,title_snapshots,next_step,scene_choice,previous_scene_revision,created_at,revision,linked_next_task_id}。
允许同一天多次收尾，以最新一条作为首页卡，历史可查看；不锁定用户一天只能结束一次。
跨文件保存顺序：先保存收尾和scene命令outbox→应用F07偏好→标记命令完成。崩溃后重复应用同命令不重复生效。
恢复旧布景须用户点“恢复”，且场景revision仍匹配；若用户已手动改布景，不覆盖其新布局。

### 异常与验收
- 保存失败保留收尾草稿，不播放“都收好啦”；源便签删除时显示标题快照与“原记录已删除”。
- 昨天记录跨时区继续可读；不把本地日期重新计算后改写历史日期。
- 没有任何笔记和任务也可完成仪式；不强求填写。
- 低动态直接显示“已收好”，无熄灯闪动；勿扰下无声音，默认所有功能本就不新增音效。
验收：零条记录可完成；双击确认只存一份；中途退出可续填；不改DSH会话/专注/提醒；崩溃恢复不重复新建任务；用户新布局不被旧收尾覆盖。
延伸：自定义收尾清单、每周手动回看、不同工作区独立收尾；不做自动绩效评级。

## F04 陪我听音乐：跟着气氛，不装作听懂了歌曲

### 用户场景与范围
用户已在播放器播放音乐，主动让Mimi一起听。现有SMTC继续负责播放控制，新功能只增加陪伴表现。
无音频采集、歌词抓取、曲库请求和BPM识别；默认不保存听歌历史。

### 页面与流程
- 现有媒体栏增加“陪我听”开关，状态：关闭/轻轻陪听/静态陪听/等待播放器；强度仅轻微、标准两档。
- 用户开关开启→检查SMTC能力与标题/播放状态→有播放时A11佩戴→进入轻摆；无播放则显示等待，不自动启动播放器。
- 开启时无SMTC依赖：显示不可用原因和关闭按钮，不重复轮询安装、不自动执行安装命令。
- 同一播放器换曲：只更新现有标题，佩戴动作不重播；曲目变化最多每2秒合并一次。
- 暂停/停止：5秒内停止摆动并摘下临时耳机；保持用户跟听偏好为开，恢复播放时经过2秒稳定确认才重入。
- 用户关闭开关：立即停止，清理临时装饰；不会暂停真实播放器。
- 勿扰/低动态：使用静态耳机且不摆动；用户正在回答问题时仅静态，不叠加节奏气泡。

### 状态与数据
runtime：off → waiting → entering → listening → suspended/waiting；关闭任意阶段→exiting→off；关闭动作超时直接清理。
MusicCompanionPrefs{enabled,strength,reduced_motion_override:false,revision}；当前播放器ID、标题、播放状态只在内存保留。
enabled只在当前桌宠生命周期生效，重启默认为关；strength可以持久保存，避免静默重新进入跟听。
跟听耳机是 appearance 临时覆盖层，不覆写F05穿搭；取下后恢复原头饰。冲突槽优先用户穿搭，耳机可用无头饰静态徽记降级。

### 异常、延伸与验收
SMTC断连→停止摆动、等待能力恢复；轮询线程错误不重启整个桌宠；源播放器切换需要2秒稳定期。
延伸：用户手选跟随播放器、允许的自定义静态耳机；音频节拍分析必须作为另行设计的显式权限，不在本稿首版。
验收：5秒内响应暂停；1分钟换曲30次不重复佩戴30次；关闭不影响播放器；低动态零连续摆动；禁用/关闭时无残留计时器与头饰覆盖。

## F05 小衣帽架：试穿有惊喜，保存有边界

### 用户场景与范围
给Mimi换一个蝴蝶结、围巾或小挂件，存成搭配。不是必须签到、付费抽取或刷好感才能使用的系统。
首版只提供内置审核配饰，三个槽位：head、neck、charm；不接受任意代码型插件或远程素材地址。

### 页面与流程
1. 衣帽架显示当前造型、三个槽位和内置物品列表；可“清空此槽”，默认裸装合法。
2. 点物品进入试穿，右上明确显示“预览中”；已保存搭配不立即改变。
3. 切物品只替换preview，不写磁盘；取消/关闭恢复原搭配；保存成功才提交并请求A06。
4. “展示一下”只在兼容A07时开放，否则显示静态预览；不把全帧动画用整套扭曲变形冒充配饰适配。
5. 可保存3套自命名搭配（名字≤20字），一键应用仍支持撤销到前一套；删除方案不删除素材。
6. 某动作未适配配饰时，该槽暂时隐藏，不显示错误；返回支持姿势时恢复。列表明确“待机适配/完整适配”。

### 素材、状态与数据
WardrobeItem{id,slot,asset_id,anchor_map,occlusion_layer,compatible_actions,conflict_tags,asset_version}。
Outfit{id,name,slots:{head,neck,charm},revision}；Appearance{active_outfit_id,fallback_slots,revision}；preview只在内存，不写active。
锚点由美术人工校准，使用规范画布坐标；不能假设单个头部锚点能覆盖转身/喝水/低头全部帧。
资源加载异步：选中项标loading；预览generation变化则丢弃旧加载结果，防止快速换装闪回旧配饰。
F04耳机和F06临时物品分独立临时层，关闭后恢复穿搭；脸部、问题卡优先保持可见。

### 异常、延伸与验收
缺图/版本不兼容→只隐藏缺失物品并标“暂不可用”，不清空用户整套方案；保存失败保留预览和原搭配。
新物品如需导入，后续仅允许本地图片包、文件大小/路径/schema限制与预览，不执行脚本。
延伸：颜色变体、按用户主动选择切工作/休息搭配、导出搭配码（仅物品ID，不含本地路径）；不按好感封锁基础功能。
验收：连续切换50次最终结果为最后一次；取消不落盘；重启恢复已存造型；不兼容动作无穿模；缺图不崩溃；跟听结束恢复原头饰。

## F06 桌边玩具盒：玩一小会儿，随时回工作

### 用户场景与范围
用户想短暂松口气，主动选一件小玩具。默认不自动弹出，不以连续点击或得分给好感加成。
首版两种明确玩法：滚球（A08/A09）和接纸星（A10的主动试玩）；共用同一玩具会话，不扩展成游戏大厅。

### 页面与流程
- 玩具盒卡：选择滚球/纸星，显示“约20秒，随时结束”；开始前确认当前空间可见。
- 滚球：Mimi推出一个球；用户点击玩具自身可轻推一次，球按受限轨迹运动；20秒结束或点“收好”。
- 纸星：用户点击卡片“落一颗”，一颗星落入角色交互区，A10接住；同屏最多1颗，每轮最多3颗。
- 所有鼠标点击只在玩具可见命中区和卡片捕获；不透明全屏窗口只为动画而拦截桌面输入的方案不采用。
- Esc只在玩具卡/玩具窗口获得焦点时处理，不注册全局键盘钩子；无焦点时仍有固定“收好”按钮与桌宠菜单入口。
- 拾取桌宠、切换屏幕、打开问题卡、锁屏或主动关闭任一情况结束本轮；不自动重开。

### 状态、物理与数据
ToySession：idle → preparing → playing → ending → idle；任何阶段关闭可直接cleanup。
ToySession{id,type,start_monotonic,deadline_monotonic,seed,objects,interaction_count}仅内存，不恢复中断游戏。
玩具选择偏好可持久化；不保存成绩、连续天数、点击轨迹。球的速度有上限，固定步长积分且每帧步数有上限，休眠后直接结束不追算。
活动边界只用当前显示器可用矩形，不用跨屏并集防止球掉入显示器间隙；窄屏改为卡片内试玩。

### 异常、延伸与验收
准备资源失败则回idle并提示，清理所有部分创建的窗口；timeout兜底结束；context manager/统一cleanup释放定时器、对象和临时配饰。
低动态：滚球改为点一下静态位置变化，纸星直接显示接住结果；不强迫用户体验运动。
延伸：纸飞机短轨迹、吹泡泡等需新设计与美术；不在首版无节制加玩具种类。
验收：每轮≤20秒；同屏球≤1、星≤1；100轮开始/结束后对象数和缓存趋于稳定；背景不拦点击；拔屏/锁屏立即收起；与F07碰撞关闭也可正常玩。

## F07 可收起的小布景：Mimi有自己的角落，不霸占桌面

### 用户场景与范围
用户为Mimi摆个小垫子、书角和灯，工作时可一键隐藏。它是装饰，不移动真实文件、不读取其他窗口内容。
首版最多3个物件，只做摆放与叠层，不让角色站到家具上、不做家具物理碰撞。

### 页面与流程
1. 小空间选择内置场景模板或空白；模板仅替换宠物装饰，不改变系统壁纸。
2. 点“编辑布局”才出现拖动手柄、轮廓、对齐参考和保存/取消；普通模式下非交互装饰鼠标穿透。
3. 物件支持拖动、三档大小、移除；灯仅开/关与两档亮度，不跟随真实显示器亮度。
4. 布局默认跟随宠物，以角色根节点为参考偏移；用户选“固定这个角落”才改为屏幕归一化锚点。
5. 保存后关闭编辑层；一键隐藏保持布局，重新显示恢复。关闭场景时可请求A05，但关闭立即生效，不等动画。
6. F03收尾通过scene命令outbox隐藏/关灯；只改变对应字段，不重写整个布局。

### 状态与数据
Scene：hidden/visible/editing；editing包含base_revision和draft，取消恢复前状态；隐藏时也不丢draft，回编辑由用户选择恢复。
Scene{id,visible,placement_mode,monitor_hint,anchor_normalized,items[{id,asset_id,offset,scale,z,light_on,light_level}],revision}。
屏幕ID只是提示，布局使用归一化坐标与可用矩形校正；断屏先选宠物当前屏，再主屏，保证至少可抓取区域可见。
层级：背景道具→角色后侧→角色→前道具→业务卡片；问题/批准卡最高，场景无权遮盖。
位置变化只更新内存，拖动结束保存一次，避免60Hz写磁盘；换DPI用逻辑像素，不把物理像素原样恢复。

### 异常、延伸与验收
缺素材只跳过该物件并保留配置；渲染失败关场景、不关宠物；编辑期间出现问题卡先保存草稿并让出交互。
多屏移位不自动反复改写用户原屏锚点：保留偏好与当前fallback位置，待原屏回来用户决定恢复。
延伸：更多内置布景、手动季节主题、按工作区独立布局；家具碰撞另做物理规格，不靠贴图假装已经支持。
验收：普通模式装饰点击穿透；编辑取消无落盘；F03不覆盖新revision；负坐标副屏/断屏/200%DPI不丢物件；隐藏后零透明阻挡窗口、无发光定时器。

## F08 温柔健康小卡：少打扰，也能记得休息

### 用户场景与范围
用户自愿配置喝水、看远、肩颈活动的小卡，以实际作息为准。不是医疗计划或后台健康监测。
和已有一次性提醒的区别：新增重复计划、活跃时段、每日配额、今日停用、恢复合并和执行记录。

### 页面与首次设置
- 默认全部关闭。用户开启一种类型时选择间隔（15–180分钟）、活跃时段、星期、每日展示上限（1–8次）、时区。
- 给示例值但不当作医疗推荐：例如仅工作日09:00–18:00，每60分钟，最多4次；用户确认后才建立计划。
- 支持最多2段时窗，可跨午夜；跨午夜时窗属于开始日，展示配额按实际显示所在本地日计算。
- 小卡只有三个主按钮：“做过了”“稍后10分钟”“今天先关”；更多菜单有“关闭此计划”。不显示红色逾期倒计时。

### 调度与操作流程
1. 启用/编辑计划后，从当前时刻起取“启用时间+间隔”与下一个有效时窗起点中的后续有效候选；时窗外不触发。
2. 每个有效时窗第一张在起点后一个间隔产生，不在刚开电脑时立即催促；跨时窗重新锚定，不累积前一时窗次数。
3. due到来检查锁屏/勿扰/是否已有问题卡/本地日配额/同类pending；满足才展示，否则转deferred待面板查看。
4. “做过了”记录用户自报完成，卡片结束。喝水可请求A02，肩颈可请求A01；看远使用静态提示，不代替真实动作检测。
5. “稍后”只安排一次10分钟延期，最多2次；超出有效时窗则结束本次，不跨夜补发。
6. “今天先关”设置 muted_until 为计划时区次日本地零点，此日未来触发均略过；不改变永久enabled。
7. 恢复桌面时合并离线候选，每计划只保留一个、总共最多一张汇总卡；超过60分钟的旧候选过期，不集中补发。
8. 达到每日实际展示上限，不再弹卡；勿扰面板记录不得在解除勿扰时绕过上限成批弹出。

### 时间与状态模型
Schedule{id,kind,enabled,timezone,weekdays,windows,interval_minutes,daily_display_cap,muted_until,revision}。
Occurrence{id,schedule_id,local_date,window_id,scheduled_at,status,snooze_count,displayed_at,completed_at}。
状态：scheduled → due → displayed/deferred → completed/dismissed/expired；displayed → snoozed → due，最多2次。
occurrence_id由schedule_id+schedule_revision+window日期+槽位生成；用户点击操作带expected_revision，避免重复完成。
调度用时区感知墙钟，展示动画用monotonic；系统时钟前拨跳过旧候选，回拨靠occurrence去重。
DST跳过不存在的本地时刻，重复本地时刻仅取较早一次；下一次计算从当前时刻后开始，不逐条回放半年历史。
计划时区默认采用系统IANA时区，后续系统时区改变时询问“跟随新时区/保持”，确认前按旧时区继续并标明；历史记录不改日期。

### 配额、数据与异常
每日展示计数包含snooze重现，每次实际出现都消耗一次；单次展示重复渲染不重复计数。各计划有自己的配额，再加全局每日上限8张。
deferred在面板有一条合并提示；用户主动打开查看不算自动展示次数；手动完成不生成伪造自动展示记录。
默认仅保存30天最近执行状态，可一键清除；不存饮水量、生理指标、键鼠轨迹；无好感扣分。
存储失败仍允许当次关闭，并记录运行期抑制避免重复弹窗；提示重启后设置可能未保存。服务端序列化tick与用户写操作，避免恰逢午夜竞态。
停用功能立即取消未展示候选、移除卡片；不影响用户原先设置的一次性提醒。

### 延伸与验收
延伸：自定义卡片文案、用户自选更短静态提示、按工作/休息模板显式切换；自动感知作息需另行论证，不默认采集。
验收：休眠8小时只合并一张且旧记录过期；今天关闭跨零点正常恢复；DST两种跳变不重复；时钟回拨不重发；每日配额计数准确；同一时刻多个计划仅一张卡；不改已有提醒；忽略卡片不掉好感。

## 9. 跨功能场景与冲突规则

| 场景 | 正确行为 |
|---|---|
| 编辑便签时收到DSH问题 | 暂存草稿，问题入口置顶，不强行抢走正在组合的中文输入；用户可切换后回来 |
| 玩球中用户拾取Mimi | 先停止玩具并释放对象，再按原物理逻辑拾取；不让玩具状态阻止拖拽 |
| 健康卡到期且专注勿扰开启 | 只进入待处理；不弹卡、不抢动作、不停止计时 |
| 戴着用户头饰开启跟听 | 不覆盖持久造型；优先兼容临时耳机，否则静态徽记，退出恢复 |
| 收尾保存后用户立即改布景 | 收尾只按revision提交必要字段，新布局不得被延迟到来的旧命令覆盖 |
| 完成任务恰好存储失败 | 保留待提交UI，不显示已完成，不请求星星动画；用户可重试 |
| 提交成功但HTTP超时 | 原request_id重试，或query核对新revision；不重复新增、奖励或播放 |
| 进程重启 | 恢复已保存便签/任务/穿搭/布景/计划；不恢复玩具运动、跟听开关和历史动画 |

## 10. 实施切片与完成定义

### 第一期：F01 + F02，配 A03/A10/A02
先做独立服务、JSON存储与单元测试；再升级能力握手/query与动作白名单；完成Qt/Web最小卡片；最后接美术与Director。
可先无动画交付：便签/任务功能正常，缺素材入口明确降级。A02可用户主动预览，F08未完成前不伪装成已接健康计划。

### 第二期：F03 + F08
复用一期记录与outbox，先补收尾恢复与健康时区调度测试；健康计划默认关，完成锁屏/勿扰/时钟跳变验收再开放。

### 第三期：F05 + F07
先统一道具层、锚点、资源预算和布局模式；出一套完整兼容美术，不一口气做大量未适配配饰。

### 第四期：F04 + F06
接现有媒体状态、临时装饰仲裁和可释放玩具会话；在资源与输入穿透回归通过后开放。

### 全部功能共用完成门槛
- 数据：正常保存、冲突、重启、损坏备份、磁盘失败、请求重试测试通过。
- UI：中文输入、键盘导航、焦点恢复、125%/150%/200%DPI、负坐标多屏与断屏通过。
- 行为：无素材可用、勿扰、低动态、任务突发事件、拖拽中断、退出资源释放通过。
- 协议：新旧能力协商、超长中文信封、分页预算、缺块上传、不同端revision冲突通过。
- 本地隐私：无新增凭据读取，无默认外发正文；日志不包含正文，导出/删除路径清楚。
- 提交设计不等于完成实现；上线前需实际运行与人工视觉验收，不能用文档或结构校验替代。
